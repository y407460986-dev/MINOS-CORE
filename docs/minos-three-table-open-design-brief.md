# MINOS 三表工作台 UI 生成说明

## 目标

用 Open Design 为 MINOS 三表工作台生成一版干净、工程化、适合发布前落地的 UI 原型。生成结果作为视觉和交互参考，不直接作为生产代码接入。生产落地仍基于 MINOS 当前 Tauri + React + shadcn/radix 组件结构。

## 使用方式

在 Open Design 中选择偏 dashboard / operational tool / desktop app 的 skill 或 design system，然后粘贴下面的 prompt。生成结果应优先输出单页 HTML 原型，便于我们截图、对比和转换成 MINOS 组件。

## Open Design Prompt

```text
你是一名资深工业质量软件产品设计师。请为 MINOS-CORE 设计一个桌面端三表工作台 UI 原型。

产品背景：
MINOS-CORE 是用于 PPAP / APQP / AIAG-VDA FMEA 场景的工程质量工具。用户会从图纸生成 PFD、PFMEA、Control Plan 三张关联表，并在发布前大量修改、确认、软删除、复核这些表格。用户不是普通消费者，而是质量工程师、制造工程师、项目质量负责人。他们需要高密度、清晰、稳定、可长时间工作的界面。

核心问题：
当前工作台把行编辑放在小输入框和底部操作区里，用户大量修改三表时很难受。确认 PFD 后后台生成 PFMEA 时，用户也容易感觉软件卡住。删除 AI 生成行不够顺手。

请设计的界面：
1. 主屏必须以“大面积三表编辑网格”为中心，像工程表格工具，而不是营销型 dashboard。
2. PFD / PFMEA / CP 使用顶部 tabs 切换。
3. 顶部只放必要内容：tabs、搜索、风险筛选、状态筛选、列显示、紧凑阶段状态。
4. 阶段状态要清楚显示：
   - PFD 已确认
   - PFMEA 生成中 / 已生成 / 失败
   - CP 待开始 / 生成中 / 已生成 / 失败
   状态区必须紧凑，不能抢主编辑区。
5. 表格支持单元格直接编辑：
   - 单击或双击进入编辑
   - Enter 保存到暂存
   - Esc 放弃当前单元格编辑
   - Tab 跳到下一个可编辑字段
6. 不要使用复古的固定底部批量操作条。
7. 选中单元格或多行时，显示轻量的浮动上下文工具条，包含：
   - 保存更改
   - 软删除
   - 标记为评审
   - 撤销本轮更改
8. 删除入口不要常驻成大按钮；放在行 hover、右键菜单、多选浮动工具条里。
9. 右侧可以有辅助栏，但必须可折叠，默认不要占太多空间。辅助栏内容：
   - 选中行证据摘要
   - PFD / PFMEA / CP 链路
   - 风险说明
   - 后台任务错误与重试入口
10. 视觉风格要干净、克制、专业。避免大面积渐变、夸张 hero、花哨卡片、装饰性图形。更像 Linear / Notion database / Figma properties panel / 高质量工程 SaaS，而不是营销页。
11. 表格信息密度要高，但不能拥挤。行高、列宽、状态 badge、风险颜色都要适合长时间工作。
12. 必须包含空状态、后台生成中状态、失败状态、未保存更改状态、多行选择状态。

请输出一个可运行的单页 HTML 原型，包含：
- 顶部紧凑任务状态
- 三表 tabs
- 搜索和筛选
- 大面积可编辑表格
- 选中后浮动上下文工具条
- 可折叠右侧辅助栏
- 失败 / 重试状态示例
- 未保存更改提示

不要写营销文案，不要做 landing page，不要用大 hero。整个第一屏必须就是可操作的三表工作台。
```

## MINOS 落地边界

- 保留现有 `ThreeTableWorkbench.tsx`、`WorkbenchTable.tsx`、`PreviewRail.tsx`、`InspectorPanel.tsx` 的基本职责。
- 不改后端三表生成算法。
- 不把 Open Design 直接嵌入 MINOS。
- 不在发布前引入新的大型 UI 框架。
- 生成 UI 只作为参考，落地时使用现有 React、Tailwind、shadcn/radix、lucide-react。

## 预期落地结果

- 三表编辑区域明显变大。
- 用户可以直接在表格内修改关键字段。
- 选择单元格或多行后，操作以浮动上下文方式出现。
- PFD 确认后，PFMEA 后台生成状态明确可见。
- 失败时显示具体阶段、错误摘要和重试入口。
- 软删除更顺手，不再依赖固定底部按钮。
