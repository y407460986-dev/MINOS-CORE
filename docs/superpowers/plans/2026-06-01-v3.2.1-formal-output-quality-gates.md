# V3.2.1 Formal Output Quality Gates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 JLV 这类真实图纸暴露出的识别、追溯、覆盖和导出缺陷在正式输出前被自动拦住，不再靠事后人工审核 Excel 才发现。

**Architecture:** 新增一个轻量的“正式输出结构质量门”，把跨表唯一性、PFMEA 到 CP 覆盖、CP 字段具体性、图纸识别疑点和导出表完整性统一投影成 `review_issues` / `manual_review_items`，并接入现有 `evaluate_export_gate()`。生成阶段只做确定性归一化，导出阶段不再放过空的人工复核清单和三表追溯矩阵。

**Tech Stack:** Python, pytest, dataclass `APQPChain`, `minos_core.quality_gates`, `minos_core.audit`, `minos_core.pipeline_chain`, `openpyxl` workbook exporters, existing OpenSpec docs.

## 背景和边界

这份计划不修当前已经导出的 JLV 报告。目标是把同类问题变成 MINOS-CORE 的系统性防线：只要未来输出里出现类似 `D00R HIMGE` 误读、盐雾红锈小时数漏提、CP ID 重复、PFMEA 未被 CP 覆盖、人工复核清单空表、三表追溯矩阵空表，正式导出就不能显示为已放行。

本轮假设：
- 草案导出仍允许生成，便于工程师查看和修正。
- 正式导出必须更严格；结构缺陷和未处理的图纸识别疑点应阻断。
- 不依赖真实 PDF、真实 OCR 或真实 AI 来做回归；用 JLV 小夹具复现缺陷形状。
- 不新增大框架，优先在现有 `evaluate_export_gate()`、`audit_chain()`、CP 归一化和 workbook exporter 上补防线。

```python
GENERIC_CONTROL_PHRASES = (
    "按图纸",
    "按规范",
    "按批准规范",
    "按工艺卡",
    "按作业指导书",
    "根据作业指导书",
)


def _audit_duplicate_control_ids(chain: APQPChain, items: list[AuditItem]) -> None:
    seen: dict[str, int] = {}
    for control in chain.controls:
        if control.deleted:
            continue
        control_id = control.control_plan_id.strip()
        if not control_id:
            continue
        seen[control_id] = seen.get(control_id, 0) + 1
    for control_id, count in seen.items():
        if count > 1:
            items.append(
                AuditItem(
                    control_id,
                    "duplicate_control_plan_id",
                    f"控制计划 ID {control_id} 出现 {count} 次，正式导出前必须唯一。",
                    "blocker",
                )
            )


def _audit_pfmea_cp_coverage(chain: APQPChain, items: list[AuditItem]) -> None:
    covered = {
        control.pfmea_id.strip()
        for control in chain.controls
        if not control.deleted and control.pfmea_id.strip()
    }
    for failure in chain.failure_modes:
        if failure.deleted:
            continue
        pfmea_id = failure.pfmea_id.strip()
        if pfmea_id and pfmea_id not in covered:
            items.append(
                AuditItem(
                    pfmea_id,
                    "uncovered_pfmea",
                    f"PFMEA 行 {pfmea_id} 没有对应控制计划行，正式导出前必须补齐或记录豁免。",
                    "blocker",
                )
            )


def _is_generic_control_text(value: str) -> bool:
    text_value = value.strip()
    if not text_value:
        return False
    return any(phrase in text_value for phrase in GENERIC_CONTROL_PHRASES)


def _audit_control_specificity(control: ControlItem, items: list[AuditItem]) -> None:
    if not control.product_process_characteristic.strip():
        items.append(
            AuditItem(
                control.control_plan_id,
                "missing_cp_characteristic",
                "控制计划缺少产品/过程特性，无法判断控制对象。",
                "blocker",
            )
        )
    for field_name, value in {
        "specification": control.specification,
        "control_method": control.control_method,
        "process_control_method": control.process_control_method,
        "parameter_specification": control.parameter_specification,
    }.items():
        if _is_generic_control_text(value):
            items.append(
                AuditItem(
                    control.control_plan_id,
                    "generic_control_text",
                    f"控制计划字段 {field_name} 只有泛化描述“{value}”，正式导出前需要具体规格、方法或受控文件编号。",
                    "blocker",
                )
            )
```

```markdown
# Proposal: V3.2.1 Formal Output Quality Gates

## Why
JLV 真实图纸复测证明，正式导出允许不等于内容可信。当前系统可能在 CP ID 重复、PFMEA 未完全被 CP 覆盖、图纸身份疑似 OCR 误读、盐雾红锈要求漏提、人工复核清单和追溯矩阵空表时仍生成看似完整的正式 xlsx。

## What
- 正式导出质量门增加结构阻断项。
- CP ID 在生成归一化阶段确定性唯一。
- 图纸识别疑点和盐雾技术要求漏项进入人工复核并阻断正式放行。
- 导出工作簿必须包含可读追溯矩阵和人工复核清单。
- 用小夹具复现 JLV 缺陷，不依赖真实 PDF、OCR 或 AI。

## Non-goals
- 不修改当前已导出的 JLV 报告。
- 不把所有 warning 都改成阻断。
- 不重写三表生成主流程。

## Acceptance
- 坏 JLV fixture 正式导出被阻断。
- 修正 JLV fixture 正式导出允许。
- 追溯矩阵和人工复核清单不再只有表头。
- 聚焦 pytest、OpenXML 可打开性和 diff 检查通过。
```

```markdown
# Design: V3.2.1 Formal Output Quality Gates

## Quality Gate
正式输出质量门继续使用 `evaluate_export_gate()` 作为唯一入口。新增结构缺陷由 `audit_chain()` 产生，severity 为 `blocker` 的审计项进入 `manual_review_items`、`review_issues`，并使 `allow_user_export=false`。

## CP ID
CP ID 不再信任模型返回值。链式生成和规则生成统一使用 `CP-` + PFMEA 后缀，例如 `PFMEA-P02-01` 对应 `CP-P02-01`。模型原始 ID 如需保留，只写入 `model_control_plan_id`。

## Drawing Risks
OCR 身份疑点和盐雾技术要求漏项先在 drawing gate 里形成 manual review item，再通过 chain metadata 带到正式质量门。未确认的 blocker 不能正式导出。

## Workbook Completeness
`三表追溯矩阵` 没有显式矩阵时从 APQPChain 的 PFD/PFMEA/CP 合成。`人工复核清单` 使用 quality gate 的 manual review items；如果为空但存在 review issues，则用 review issues 兜底。

## Regression
JLV fixture 是最小结构化失败样本，不包含真实客户图纸 PDF，不调用 OCR 或 AI。它只验证 MINOS 内部质量门能挡住已知缺陷形状。
```
