# MINOS 三表工作台 UI 方向规格

## 背景

用户希望借助 Open Design 为 MINOS 生成新的 UI 方向，但不要把 Open Design 深度接入 MINOS。当前选择的路径是：Open Design 负责生成视觉和交互原型，MINOS 生产代码仍由现有 Tauri + React 结构落地。

本次先聚焦三表工作台，因为它直接承载 PFD、PFMEA、CP 的修改、确认、软删除和后台生成状态，也是当前使用痛点最集中的区域。

## 设计目标

- 主屏大部分面积用于三表修改。
- 三表修改方式从“小输入框逐行编辑”升级为“表格内直接编辑”。
- 不使用固定底部批量操作条，避免界面复古和沉重。
- 操作跟随用户选择状态出现：单元格编辑、多行选择、浮动上下文工具条。
- 后台生成状态明确可见，让确认动作不再像卡死。
- 失败、重试、软删除、撤销本轮更改都有清楚入口。

## 页面结构

三表工作台采用四个区域：

1. 顶部紧凑状态区
   显示当前运行、PFD/PFMEA/CP 阶段状态、后台生成中或失败摘要。这个区域保持矮，不抢编辑空间。

2. 表格工具区
   显示 PFD/PFMEA/CP tabs、搜索、风险筛选、状态筛选、列显示。所有控件保持一行或紧凑两行。

3. 大面积三表编辑网格
   页面主体。用户直接在表格单元格中修改 PFD、PFMEA、CP 的关键字段。支持单元格焦点、多行选择、未保存状态。

4. 可折叠辅助栏
   默认窄栏或可收起。显示选中行证据、链路摘要、风险说明、后台任务错误和重试入口。

## 核心交互

单元格编辑：
- 单击或双击进入编辑。
- Enter 将当前编辑保存到本地暂存。
- Esc 放弃当前单元格编辑。
- Tab 跳到下一个可编辑字段。

选择与批量操作：
- 选择单元格或多行后，显示轻量浮动工具条。
- 浮动工具条包含保存更改、软删除、标记评审、撤销本轮更改。
- 删除入口不做常驻大按钮；放在行 hover、右键菜单、多选浮动工具条中。

阶段确认：
- PFD 确认后，PFMEA 进入后台生成中状态。
- 用户仍可继续浏览和整理当前表格。
- 后台任务完成后，顶部状态区更新。
- 后台任务失败时，顶部状态区和辅助栏都显示失败摘要与重试入口。

## 视觉原则

- 干净、克制、工程化。
- 像高质量工程 SaaS 或数据库编辑器，不像营销页。
- 不使用大 hero、装饰渐变、夸张卡片、复杂插画。
- 表格信息密度高，但状态、风险、未保存提示必须清楚。
- 右侧辅助栏不能喧宾夺主。

## Open Design 使用边界

Open Design 只用于生成 UI 原型、视觉方向和交互参考。生成结果不直接复制进生产代码。生产落地必须复用 MINOS 当前技术栈：

- React 18
- Tauri 2
- Tailwind CSS
- shadcn/radix UI
- lucide-react
- 现有 Python sidecar API
- 现有 edit patch / soft delete / chain stage 数据结构

## 验收标准

- 用户能在第一屏看到并操作大面积三表编辑网格。
- 用户确认 PFD 后能清楚看到 PFMEA 正在后台生成。
- 用户可以直接编辑单元格，而不是只能在底部小输入框编辑。
- 用户选中多行后能看到轻量浮动工具条。
- 用户可以软删除 AI 生成行。
- 未保存更改有明确提示。
- 后台生成失败有明确失败状态和重试入口。
- 页面在桌面常见宽度下不拥挤、不重叠、不像旧式后台。

## 暂不包含

- 不重写全局 AppShell。
- 不深度集成 Open Design 到 MINOS 内部。
- 不引入新的表格框架，除非现有 TanStack Table 无法支撑必要交互。
- 不改变后端三表生成算法。
- 不改变 PFD/PFMEA/CP 数据模型。
