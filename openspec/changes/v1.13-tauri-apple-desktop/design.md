# Design: V1.13 Tauri Apple Desktop

## Architecture Boundary
V1.13 采用清晰分层：
- `minos_core`：继续提供图纸到三表、编辑 patch、质量门、闭环任务、导出等核心能力；不得依赖前端框架。
- Tauri shell：负责窗口、文件选择、本地命令、安全边界和桌面集成。
- React UI：负责 Apple 风格工作台、三表编辑、联动预览、闭环任务和导出体验。
- PySide6 legacy：冻结为旧桌面路径，只做必要维护和回归，不承载新桌面能力。
- `minos_platform`：保留平台化方向，但不作为本次桌面主后端。

## Desktop Workbench
主界面采用桌面工作台结构：
- 左侧：项目、图纸、三表、联动、闭环、导出导航。
- 中央：当前任务主工作区，例如图纸选择、三表编辑器或联动预览。
- V1.14.17 已废弃右侧固定检查器；质量门、复核项、知识推荐、行动项和导出阻断原因改由主工作区和底部 `PreviewRail` 承载。
- 底部或顶部：当前项目状态、草案/正式状态、保存和导出状态。

## Apple Style Direction
- 安静、清晰、低噪声，优先服务工程师反复编辑和核对。
- 采用紧凑表格、主区分栏、底部选中行摘要、原生感按钮和清楚的状态反馈。
- 不使用营销式 hero，不用装饰性大卡片堆叠。
- 1280x800 是最低验收视口，核心工作流必须无重叠。

## Data Flow
- React 不直接改写 core 内部结果结构，所有变更通过明确 command 或服务函数提交。
- 三表编辑统一形成可审计 edit patch。
- 闭环任务处理复用既有推荐、行动项、复核和质量门语义。
- 导出必须读取当前草案/正式状态和质量门结果，不能绕过 core 规则。

## Compatibility
- PySide6 旧界面保持 legacy 状态，便于旧验收和回归对比。
- V1.13 新工作台可以逐步接入，不要求一次删除旧桌面目录。
- OpenSpec 和流程记录先建立迁移边界，再由实现子任务逐步落地。
